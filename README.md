# 사건관리 대시보드 — 배포 가이드

Claude(Anthropic) 서버에 의존하지 않고, 무료 서비스(Firebase + GitHub Pages)만으로 크롬 브라우저에서
접속해 쓸 수 있는 개인용 웹앱입니다. 아래 순서대로 따라 하면 약 20~30분 안에 본인만의 주소로
접속할 수 있습니다.

- 데이터 저장: **Firebase Firestore** (무료 Spark 플랜)
- 로그인 보호: **Firebase Authentication** (이메일/비밀번호, 본인 계정 1개)
- 호스팅: **GitHub Pages** (무료 정적 호스팅)

---

## 1단계. Firebase 프로젝트 만들기

1. https://console.firebase.google.com 접속 후 구글 계정으로 로그인
2. **"프로젝트 추가"** 클릭 → 프로젝트 이름 입력 (예: `lawyer-dashboard`) → 애널리틱스는 꺼도 무방 → 프로젝트 생성

### 1-1. Firestore Database 활성화
1. 왼쪽 메뉴 **빌드 > Firestore Database** 클릭 → **"데이터베이스 만들기"**
2. 위치는 `asia-northeast3 (서울)` 선택 (한국 기준 속도가 가장 빠름)
3. 보안 규칙은 일단 아무거나 선택하고 만든 뒤, 아래 1-2에서 바로 교체합니다.

### 1-2. 보안 규칙 설정 (중요 — 반드시 진행)
1. Firestore Database 화면에서 **"규칙(Rules)"** 탭 클릭
2. 아래 내용(이 프로젝트의 `firestore.rules` 파일 내용)을 그대로 붙여넣고 **"게시(Publish)"**

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /matters/{matterId} {
      allow read, write: if request.auth != null;
    }
    match /meta/{docId} {
      allow read, write: if request.auth != null;
    }
    match /tasks/{taskId} {
      allow read, write: if request.auth != null;
    }
    match /todoMeta/{docId} {
      allow read, write: if request.auth != null;
    }
  }
}
```

(`tasks`/`todoMeta`는 아래 4단계에서 설명하는 별도의 **업무 To-Do 대시보드**가 쓰는 컬렉션입니다.
지금 만들지 않더라도 규칙에 미리 포함해두면 나중에 추가할 때 다시 규칙을 고칠 필요가 없습니다.)

이 규칙은 **로그인한 사용자만** 사건 데이터를 읽고 쓸 수 있게 막아줍니다. 이 단계를 건너뛰면
누구든 인터넷에서 데이터를 열람/수정할 수 있으니 꼭 설정하세요.

### 1-3. 로그인(Authentication) 설정
1. 왼쪽 메뉴 **빌드 > Authentication** → **"시작하기"**
2. **"Sign-in method"** 탭 → **"이메일/비밀번호"** 선택 → 사용 설정 → 저장
3. **"Users"** 탭 → **"사용자 추가"** → 본인이 사용할 이메일/비밀번호 입력 후 저장
   - 이 계정이 곧 대시보드 로그인 계정입니다. 다른 사람에게 알려주지 마세요.
   - 계정을 더 추가하지 않는 한 이 이메일/비밀번호를 아는 사람만 앱에 접속해 데이터를 볼 수 있습니다.

### 1-4. 웹 앱 등록 & 설정값 복사
1. 프로젝트 설정(⚙️ 아이콘) > **"프로젝트 설정"** 클릭
2. 아래로 스크롤 → **"내 앱"** → `</>` (웹 앱 추가) 아이콘 클릭
3. 앱 닉네임 입력 (예: `dashboard-web`) → Firebase 호스팅은 체크하지 않아도 됨 → 앱 등록
4. 화면에 나오는 `firebaseConfig` 객체 값을 복사합니다. 예:

```js
const firebaseConfig = {
  apiKey: "AIzaSy....",
  authDomain: "lawyer-dashboard-xxxx.firebaseapp.com",
  projectId: "lawyer-dashboard-xxxx",
  storageBucket: "lawyer-dashboard-xxxx.appspot.com",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef123456"
};
```

5. 이 프로젝트 폴더의 **`firebase-config.js`** 파일을 열어 `YOUR_API_KEY` 등 자리표시자 값을
   위에서 복사한 실제 값으로 교체 후 저장합니다. (이 값은 비밀키가 아니라 앱 식별용 공개 설정이라
   GitHub에 그대로 올려도 안전합니다 — 실제 보호는 1-2단계의 보안 규칙과 1-3단계의 로그인이 담당합니다.)

## 2단계. GitHub 저장소 만들고 GitHub Pages로 배포

1. https://github.com 에서 계정이 없다면 무료로 가입
2. 우측 상단 **"+" > "New repository"** → 저장소 이름 입력 (예: `lawyer-dashboard`) →
   **Public**으로 설정(GitHub Pages 무료 사용을 위해 Public 권장) → **Create repository**
3. 저장소 페이지에서 **"uploading an existing file"** 링크 클릭 (또는 "Add file > Upload files")
4. 이 폴더 안의 파일들을 전부 드래그해서 업로드:
   - `index.html`
   - `style.css`
   - `app.js`
   - `firebase-config.js` (실제 값으로 수정한 버전)
   - (참고용) `firestore.rules`, `README.md`
   - `todo/` 폴더 전체 (업무 To-Do 대시보드를 함께 쓸 경우 — 4단계 참고. GitHub 업로드 화면에
     `todo` 폴더째로 드래그하면 하위 파일들이 `todo/index.html`처럼 그대로 업로드됩니다.)
5. 하단에 커밋 메시지 입력 후 **"Commit changes"**

### 2-1. GitHub Pages 활성화
1. 저장소 상단 메뉴 **Settings > Pages** 이동
2. **"Build and deployment"** 의 Source를 **"Deploy from a branch"**로 선택
3. Branch를 `main` (또는 `master`), 폴더는 `/ (root)` 선택 후 **Save**
4. 1~2분 후 같은 화면 상단에 `https://<본인계정>.github.io/lawyer-dashboard/` 형태의 주소가 생성됩니다.

### 2-2. Firebase에 배포 주소 등록 (승인된 도메인)
GitHub Pages 주소가 Firebase 로그인에서 차단되지 않도록 등록해야 합니다.
1. Firebase 콘솔 > Authentication > **Settings** 탭 > **"승인된 도메인(Authorized domains)"**
2. **"도메인 추가"** → `<본인계정>.github.io` 입력 후 추가

## 3단계. 접속 & 사용

1. 크롬에서 `https://<본인계정>.github.io/lawyer-dashboard/` 접속
2. 1-3단계에서 만든 이메일/비밀번호로 로그인
3. **사건관리 탭**: "+ 사건 등록"을 누르면 사건 하나에 대해 아래 내용을 한 번에 등록/수정합니다.
   - **진행상태**: 미접수 → (접수사건) → 진행사건 → 완료사건 이 기본적으로 자동 분류됩니다. 판단 기준은 아래와 같습니다.
     - **민사/가사/기타가 하나라도 섞여 있는 사건** (형사와 같이 체크된 경우 포함):
       1. 사건번호가 없거나, 접수서류 건수가 사건번호 건수보다 적으면 → **미접수** (건수가 서로 안 맞아도 미접수)
       2. 접수서류 건수가 사건번호 건수 이상으로 맞춰지면 → **접수사건**
       3. 그 상태에서 기일·제출서류·상대방 제출서류 중 하나라도 등록되면 → **진행사건**
       4. 그중 "선고기일" 기일이 등록되어 있고 그 날짜가 오늘보다 이전이면 → **완료사건**
     - **형사만 단독으로 체크된 사건** (민사/가사/기타 미체크): 접수서류 개념이 따로 없는 경우가 많아 접수사건 단계를
       건너뜁니다.
       1. 기일·제출서류·상대방 제출서류가 하나도 없으면 → **미접수**
       2. 그중 하나라도 등록되면 바로 → **진행사건**
       3. 그중 "선고기일" 기일이 등록되어 있고 그 날짜가 오늘보다 이전이면 → **완료사건**

     (구분 자체는 표시용이지만, "형사만 단독 체크"인지 여부는 위처럼 판단 경로를 바꾸는 데 쓰입니다.
     형사 진행현황(수사중~불기소)은 표시용일 뿐 자동분류 계산에는 영향을 주지 않습니다.)
     필요하면 "이 상태로 수동 변경"을 눌러 직접 고정할 수 있고, "자동분류로 전환"으로 언제든 되돌릴 수 있습니다.
   - **구분**: 민사/형사/가사/기타 중 중복 체크 가능. 형사를 체크하면 수사중~불기소까지의 진행현황을 별도로 기록합니다.
   - **사건번호**: 관할기관(법원/경찰서/검찰 등)별로 여러 건 등록 가능 (예: 법원 사건 + 경찰 사건 동시 진행 중인 경우).
   - **원고/피해자**, **피고/피고인**: 각각 이름·연락처를 여러 명 등록 가능하며, 표에서 원고/피해자는 빨간색,
     피고/피고인은 파란색 칩으로 구분되어 표시됩니다.
   - **담당변호사**: 대표님/천솔비/김도영 중 선택.
   - **접수서류 / 제출서류(우리 측) / 상대방 제출서류**: 날짜와 서류명을 각각 여러 건 기록.
   - **보정명령**: 발령일·기한·내용·완료 여부를 기록하면 기한까지 남은 일수가 D-day 배지로 자동 표시됩니다
     (D-3 이내는 주황, 기한 경과는 빨강, 완료 처리하면 회색 "완료" 표시).
   - **기일**: 날짜·시간·종류(변론기일/선고기일/조정기일/심문기일/기타)·법정·장소(또는 영상재판 링크)를 여러 건 등록.
   - **메모**: 날짜별로 자유롭게 메모를 여러 건 남길 수 있습니다.
   - 표 상단의 서브탭(전체건/미접수/접수사건/진행사건/완료사건/천솔비 담당사건/김도영 담당사건)으로 빠르게 걸러볼 수 있고,
     검색창에 사건번호·이름·사건명을 입력해 검색할 수 있습니다.
   - 사건 목록은 기본적으로 의뢰인(빨간 칩)으로 지정된 사람 이름의 가나다순으로 정렬됩니다 (의뢰인이 여러 명이면
     처음 등록한 이름 기준). "원고/피해자"·"피고/피고인" 표 머리글을 클릭하면 그 열의 이름 기준으로 오름차순/
     내림차순 정렬을 직접 바꿀 수 있습니다 (다시 클릭하면 방향 전환).
   - 화면 맨 위 노란 메모칸은 스크롤해도 고정되며, 자동 저장되는 전체 공용 메모입니다.
4. **캘린더 탭**: 이번 달 캘린더에 모든 사건의 기일이 표시됩니다.
   - 선고기일은 초록색, 그 외(변론·조정·심문 등) 기일은 주황색으로 구분됩니다.
   - 기일을 클릭하면 해당 사건이 바로 열립니다. 항목에 마우스를 올리면 사건번호·의뢰인·상대방·법정·장소 정보를 볼 수 있습니다.
   - "‹ 이전달 / 이번달 / 다음달 ›" 버튼으로 다른 달도 볼 수 있습니다.
5. **종결 탭**: 사건관리 탭 또는 사건 상세에서 "종결"을 누르면 이 탭으로 이동됩니다 (삭제가 아니라 보관 처리).
   - 목록의 사건 행을 클릭하면 사건관리 탭과 동일하게 상세 정보 모달이 열려 내용을 확인/수정할 수 있습니다
     (버튼 영역을 클릭하면 모달이 열리지 않고 해당 동작만 실행됩니다).
   - "다시 열기"로 언제든 사건관리 탭으로 되돌릴 수 있습니다.
   - "영구종결"(개별) 또는 상단의 "전체 영구종결"(일괄)을 누르면 Firestore에서 완전히 삭제되어 되돌릴 수 없습니다.
     삭제 전 상단의 "CSV 백업" 버튼(종결된 사건만 따로 내려받기) 또는 사건관리 탭의 CSV/JSON 백업 버튼으로
     미리 백업해두는 것을 권장합니다.

여러 기기(사무실 PC, 집, 휴대폰 크롬 등)에서 같은 주소로 로그인하면 Firestore를 통해
실시간으로 같은 데이터가 동기화됩니다.

> 참고: 이번 개편으로 Firestore 데이터가 기존 `cases` 컬렉션에서 새 `matters` 컬렉션으로 바뀌었습니다.
> 예전 `cases` 컬렉션에 있던 데이터는 새 대시보드에 더 이상 표시되지 않습니다 (자동 삭제되지는 않으므로,
> 필요 없다면 Firebase 콘솔에서 나중에 직접 지우셔도 되고, 그냥 남겨두어도 무방합니다).

## 4단계. 업무 To-Do 대시보드 (별도 주소, 같은 로그인 계정)

사건관리 대시보드와는 별개로, 개인 업무를 칸반 보드로 관리하는 **To-Do 대시보드**가 `todo/` 폴더에
들어있습니다. 아이디/비밀번호(로그인 계정)는 사건관리 대시보드와 완전히 동일하게 재사용하고,
접속 주소만 별도로 나뉩니다. Firestore 데이터도 `tasks`/`todoMeta` 컬렉션으로 분리되어 있어
사건관리 데이터(`matters`/`meta`)와 서로 섞이지 않습니다.

### 4-1. 설치
1. 위 2단계에서 이미 저장소를 만들고 GitHub Pages를 켰다면, **추가로 할 일은 `todo/` 폴더를
   저장소에 업로드하는 것뿐**입니다 (2단계 4번 참고). `todo/firebase-config.js`는 따로 없으며,
   `todo/app.js`가 저장소 루트의 `firebase-config.js`를 한 단계 위 경로(`../firebase-config.js`)로
   그대로 불러와 쓰므로 설정값을 두 번 입력할 필요가 없습니다.
2. 1-2단계에서 안내한 `firestore.rules`에 `tasks`/`todoMeta` 규칙이 이미 포함되어 있는지 확인하고,
   빠져 있다면 위 내용으로 다시 게시(Publish)하세요.
3. 별도의 GitHub Pages 설정이나 Firebase 승인된 도메인 추가는 필요 없습니다 (같은 저장소, 같은 도메인).

### 4-2. 접속 & 사용
1. 크롬에서 `https://<본인계정>.github.io/lawyer-dashboard/todo/` 접속 (사건관리 대시보드 주소 뒤에 `todo/`를 붙인 주소)
2. 사건관리 대시보드와 동일한 이메일/비밀번호로 로그인
3. **칸반 보드 탭**
   - 화면 맨 위 노란 메모칸: 스크롤해도 고정되는 자동 저장 메모장입니다.
   - 상단 통계 타일: 전체 업무 / 오늘 마감 / 기한 초과 / 완료됨 건수를 자동으로 보여줍니다.
   - "+ 새 업무"로 제목·분류·중요도·진행 상태·마감일·메모를 입력해 카드를 만들 수 있습니다.
   - 칼럼은 **할 일 / 진행 중 / 기타 부가 업무** 3개이며, 카드를 **마우스로 드래그해서** 같은 칼럼 안에서
     순서를 바꾸거나 다른 칼럼으로 옮길 수 있습니다. 옮긴 순서와 칼럼은 즉시 Firestore에 저장되어
     다른 기기에서도 동일하게 보입니다.
   - 카드 오른쪽 위 ✓ 버튼을 누르면 바로 "완료" 처리되어 완료 탭으로 이동합니다.
   - 카드를 클릭하면 수정/삭제 모달이 열립니다.
   - 검색창과 분류/중요도 드롭다운으로 보드를 필터링할 수 있습니다.
   - 카드 왼쪽 테두리 색: 빨강(높음)/주황(보통)/파랑(낮음)으로 중요도를 표시합니다. 마감일 배지는
     오늘 마감이면 주황, 기한이 지났으면 빨강으로 표시됩니다.
4. **완료 탭**: 완료 처리된 업무 목록입니다. "복원"으로 다시 할 일로 되돌리거나 "삭제"로 완전히 지울 수 있습니다.

> 참고: "주간 루틴" 탭과 별도의 "메모" 탭은 이 대시보드에는 없습니다 (메모는 칸반 보드 상단에
> 고정된 메모장 하나로 통합했습니다).

## 참고 / 주의사항

- Firebase 무료(Spark) 플랜은 읽기/쓰기 횟수와 저장 용량에 여유로운 무료 한도가 있어 1인 로펌/개인 변호사
  사용량으로는 사실상 비용이 발생하지 않습니다.
- 로그인 계정의 이메일/비밀번호는 곧 사건 데이터에 대한 접근권한이므로 안전하게 보관하세요.
- 별도 자동 백업은 없으므로, 중요한 사건 데이터는 주기적으로 Firebase 콘솔의 Firestore 데이터를
  확인하거나 내보내기(Export)하는 것을 권장합니다.
- 담당변호사 목록(대표님/천솔비/김도영)은 `index.html`에서 `id="f-lawyer"` select의 `<option>`을
  직접 수정해 자유롭게 추가/변경할 수 있습니다.
- CSV/JSON 백업 버튼(사건관리 탭 상단)으로 언제든 전체 사건 데이터를 파일로 내려받아 보관할 수 있습니다.
